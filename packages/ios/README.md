# OsonaiSDK for iOS

The Osonai chat for a native iOS host app (a customer company's app that has the Osonai SDK inside). It is a
Swift package (iOS 15+) with three parts:

- `Osonai`: the config, the host app's tool functions, what is on screen (`context`), `send`, `reset` and the callbacks.
- `OsonaiChatViewController`: the chat screen for UIKit, on `WKWebView`.
- `OsonaiChatView`: the same screen for SwiftUI.

The chat screen, the agent loop and the connection to the Osonai server are one HTML file in the package
(`Sources/OsonaiSDK/Resources/osonai-chat.html`, generated by `packages/embed`). The host app adds only its own
tool functions. They run in the host app, with the host app's own signed-in user token. The token never goes to
the chat page. The bridge protocol is in `docs/mobile.md`.

## Install

The package is the repository `https://github.com/zohidjon-m/osonai` (its `Package.swift` is at the root).

**Xcode**: File → Add Package Dependencies… → enter `https://github.com/zohidjon-m/osonai` → "Up to Next
Major Version" from `0.1.0` → add the library `OsonaiSDK` to your app target.

**XcodeGen**:

```yaml
packages:
  OsonaiSDK:
    url: https://github.com/zohidjon-m/osonai
    from: 0.1.0
targets:
  YourApp:
    dependencies:
      - package: OsonaiSDK
```

**Package.swift**:

```swift
dependencies: [.package(url: "https://github.com/zohidjon-m/osonai", from: "0.1.0")],
targets: [.target(name: "YourApp", dependencies: [.product(name: "OsonaiSDK", package: "osonai")])]
```

### Network settings

The chat page calls the Osonai server from inside the web view. Over **https**, the host app needs no setting.

To reach an **http** Osonai server (a test server on the local network), the test app has this one key in
`Info.plist`. Use it for a test build only. In production, use https and no key.

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key><true/>
</dict>
```

What was run: the test app with only this key, on the iOS 26.5 simulator. Its own calls to the http Bozor shop
backend server and the chat page's calls to the http Osonai server both worked (the UI smoke run). Not run on a
device. Do not add `NSAllowsArbitraryLoadsInWebContent` next to it: Apple's documentation says that iOS then
ignores `NSAllowsArbitraryLoads`.

The chat page loads from a file, so its origin is `null`. The Osonai server must answer CORS with
`Access-Control-Allow-Origin: *` (`npm run serve -- --cors '*'`).

## Usage

Create one `Osonai` after the user signs in, and register a function for each tool of the manifest.

```swift
import OsonaiSDK

let osonai = Osonai(config: OsonaiConfig(
    runtimeURL: URL(string: "https://osonai.example.com")!,
    appKey: "osk_pub_…", // the app's publishable key
    manifest: try Data(contentsOf: Bundle.main.url(forResource: "manifest", withExtension: "json")!),
    title: "Bozor assistant",
    greeting: "Hi! I can search products, manage your cart and check orders.",
    suggestions: ["Find red sneakers", "What is in my cart?"],
    placeholder: "Type a message",
    theme: OsonaiTheme(primary: "#0F766E", mode: .system),
    showClose: true
))

osonai.tool("add_to_cart") { args in
    try await api.addToCart(args["productId"] as! String, args["quantity"] as? Int)
}
osonai.tool("view_cart") { _ in try await api.getCart() }

osonai.context = ["current_screen": "product", "current_product_id": "p_106", "current_product_name": "Ceramic Teapot"]
osonai.onTurnEnd = { text, tools in refreshCart() }   // tools: the names of the tools that ran
osonai.onClose = { closeChat() }
osonai.onError = { message in print(message) }
```

**SwiftUI**: show the chat full screen. The page handles the safe area itself, so add `.ignoresSafeArea()`.

```swift
.fullScreenCover(isPresented: $chatOpen) {
    OsonaiChatView(osonai: osonai).ignoresSafeArea()
}
```

**UIKit** (not tested; the test app uses SwiftUI):

```swift
let chat = OsonaiChatViewController(osonai: osonai)
chat.modalPresentationStyle = .fullScreen
present(chat, animated: true)
osonai.onClose = { [weak chat] in chat?.dismiss(animated: true) }
```

`osonai.send("What is in my cart?")` sends a message as if the user typed it. `osonai.reset()` starts a new
conversation.

### Tool functions

- `args` are the arguments after the Harness validated, resolved and bound them, with the host app function names
  of the manifest (for example `productId`, not `product_name`).
- Return any JSON value (dictionaries, arrays, strings, numbers, booleans, `nil`) or an `Encodable`. A `Date`
  inside an `Encodable` becomes ISO 8601 text. A `[String: Any]` dictionary or an array must hold only JSON
  values: with a `Date` in it, the call fails with "The app function returned a value that is not JSON."
  The Harness sends only the manifest's `output_fields` to the model.
- A thrown error answers the model with `ok: false` and a message: the `errorDescription` of a `LocalizedError`;
  the `localizedDescription` of an `NSError`, a `URLError`, a `CocoaError` or an error with
  `NSLocalizedDescriptionKey` in its user info; else `String(describing: error)` (also for a
  `CustomNSError` with no description text).
  Write it so the model can read it ("No product is open on screen. Ask the user which product.").
- A tool name with no function answers `ok: false`.
- The function is `@Sendable` and runs off the main thread. Each call gets exactly one answer.

## Config

| `OsonaiConfig` field | Type | Default | Meaning |
|---|---|---|---|
| `runtimeURL` | `URL` | required | the Osonai server |
| `appKey` | `String` | required | the app's publishable key, sent as `Authorization: Bearer` |
| `manifest` | `Data` | required | the host app's `harness/manifest.json`, as JSON bytes |
| `title` | `String?` | "Assistant" | the chat header |
| `greeting` | `String?` | none | the first assistant message |
| `suggestions` | `[String]` | `[]` | chips under the greeting, before the first message |
| `placeholder` | `String?` | "Type a message" | the input placeholder |
| `strings` | `[String: String]` | `[:]` | replaces built-in texts of the chat screen by key, for example `["notNow": "Hozir emas"]`; the keys are in `STRINGS` in `packages/embed/src/ui.ts` |
| `theme` | `OsonaiTheme` | `.system`, teal | `primary` (a CSS color) and `mode` (`.light`, `.dark`, `.system`) |
| `showClose` | `Bool` | `false` | a Close button in the header; a tap calls `onClose` |
| `debug` | `Bool` | `false` | the page's trace lines go to `os.Logger` (subsystem `ai.osonai.sdk`, category `chat`) |
| `userIdStore` | `OsonaiUserIdStore` | `KeychainUserIdStore()` | keeps the user id the Osonai server issued to this install ([docs/mobile.md](../../docs/mobile.md#user-identity)); pass your own to keep it elsewhere |

| `Osonai` member | Meaning |
|---|---|
| `tool(_:_:)` | registers the host app's function for a manifest tool; register before the chat opens |
| `context` | what is on screen; an open chat gets it at once, a chat that opens later gets it at start |
| `send(_:)`, `reset()` | while no chat is on screen (not open yet, or closing), they wait for the next chat |
| `onTurnEnd(text, tools)`, `onClose()`, `onError(message)` | called on the main thread |
| `onOpen(kind, id)` | the user tapped a chat card whose manifest view has `open`, for example `("product", "p_101")`; open your own screen for it. Called on the main thread |

`Osonai` is `@MainActor`: use it from the main thread.

## Known limits

- Each new chat view is a new conversation. The conversation does not stay after Close.
- One open chat per `Osonai` at a time. A second open chat replaces the first as the target of `context`, `send`
  and `reset`. A chat stops being the target when it starts to disappear (`viewWillDisappear`: closed, or
  covered by another full screen) and is the target again when it appears.
- When iOS stops the web content process (memory pressure), the chat loads again, empty.
- `osonai-chat.html` is generated. After a change in `packages/embed`, run `npm run build -w @osonai/embed` to
  write a new copy here.
- A real device that reaches a server on the local network also needs `NSLocalNetworkUsageDescription`. Not
  tested: the test app ran on the simulator only.
